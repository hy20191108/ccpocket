# ADR: デスクトップでOpenSSHを使う接続とiOS対応の範囲

- 日付: 2026-11-09
- 状態: 採用済み．iOSへの拡張は未決定．
- 対象実装: `bbdfe683`

## 背景

今回の対象はWindowsのexe版であり，アプリの画面からSSH接続とClaudeとの送受信を行えることが必要だった．端末に保存済みのSSH接続先，踏み台，鍵，SSHエージェントを利用し，アプリへ同じ認証情報を再登録する負担を避ける．

デスクトップで接続できることと，変更後のアプリをiPhoneへインストールできることは別の条件である．接続機能の実装，プラットフォームごとのビルド，署名，実機での確認を区別して判断する必要がある．

## 決定

デスクトップではOSのOpenSSHを使い，アプリ自身が接続を管理する．マシン設定にSSH接続先の別名を保存し，既存のSSH設定を利用する．コード上の対象はWindows・macOS・Linuxとし，iOSではこの接続方式を利用可能にしない．

BridgeへのHTTP・WebSocket通信は，アプリが所有するループバックの待受口からSSH子プロセスの標準入出力へ中継する．これにより，接続の終了と子プロセスの終了をアプリの切断処理に結び付ける．Bridgeの既存プロトコルは維持し，起動済みのBridgeへ接続する．リモート起動・更新は従来のSSH設定で扱う．

認証と踏み台の解決をOpenSSHへ委ねても，ホスト鍵の照合やアプリの待受口の保護は必要となる．ホスト鍵の厳密な照合，ブラウザー由来の要求の拒否，接続終了時の処理を行う．具体的な接続方法と制約は[デスクトップ版の接続手順](../desktop-ssh.md)を参照する．

## 選択肢と理由

| 選択肢 | 判断と理由 |
| --- | --- |
| OSのOpenSSHを使い，標準入出力で中継する | 採用．既存のSSH設定を使え，待受口と子プロセスをアプリ自身で管理できる． |
| アプリ内SSHクライアントへ設定を再登録する | 今回の接続方式には採用しない．保存済みのOpenSSH設定を利用する目的に対し，踏み台や認証情報の設定が重複する．従来のアプリ内SSH実装は維持する． |
| SSHのローカルポート転送を別に起動する | 今回は採用しない．SSH側の待受ポートの確保と起動状態の管理を増やすため，アプリが所有する待受口から標準入出力へ中継する． |
| Web版のローカルヘルパーへ依存する | デスクトップ接続には採用しない．exe版自身で接続を管理するため，Web版の経路とは独立させる． |

## iOSのビルド・署名・インストール

今回追加したOpenSSH接続はiOS非対応である．既存のアプリ内SSH実装がソースにあることだけでは，同等の機能をiOSで利用できるとは判断しない．iOSへの拡張方法と実機での動作確認は未決定・未実施である．

今回作成した成果物はWindows版であり，変更後の署名済みiOSアプリは作成していない．したがって，今回の成果物をiPhoneへインストールすることはできない．

iOS版を用意する場合は，次の条件を満たす必要がある．

1. iOS向けの接続機能と設定画面を実装し，動作を検証する．
2. macOSとXcodeを備えた環境でiOS版をビルドする．このWindows環境単体でのビルド成功を前提にしない．
3. 導入経路に対応する証明書・秘密鍵・プロビジョニングプロファイルを用意し，署名する．既存のCI定義に署名処理があっても，利用可能なビルド環境と署名設定が揃っている証拠にはしない．
4. 対象のiPhoneへ実際にインストールし，SSH接続とClaudeとの送受信を確認する．

ビルド環境の要件は[FlutterのiOS配布手順](https://docs.flutter.dev/deployment/ios)，署名と端末への配布は[Appleの配布手順](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices)を参照する．

## 確認済みの範囲と制約

`bbdfe683`では，Windowsのexe画面でSSH接続の設定，Claudeとの送受信，保存済み設定による再起動後の接続，SSH切断後の自動再接続を確認した．専用のテスト用Bridgeを使い，既存の稼働セッションを維持した．コミット対象の一時コピーで，関連する回帰テスト37件が成功した．静的解析には既存のスタイル指摘3件が残り，エラーと警告はなかった．macOS・Linux・iOSの実機確認は行っていない．

Windowsの動作確認には，公式Windows版の実行基盤と，変更後のソースからビルドしたDart AOT・アセットを組み合わせた成果物を用いた．実行基盤とローカルSDKのFlutterエンジンの一致を確認している．これはネイティブ部分を含む全体のローカルビルド成功や，新たな公式リリースの作成を意味しない．成果物の構成は同梱の`BUILD-INFO.txt`に記録する．

## 再検討する条件

- iPhoneへの導入を作業対象にする場合は，アプリ内SSH実装の利用方法と，ビルド・署名・導入経路を改めて決める．
- Windows版を配布用の成果物として新たに作成する場合は，対応するネイティブビルド環境を整え，配布対象そのものを検証する．

実装上の責務は[SSHトンネルサービス](../../apps/mobile/lib/services/ssh_bridge_tunnel_service.dart)と[OpenSSHの中継処理](../../apps/mobile/lib/services/open_ssh_bridge_tunnel.dart)を参照する．
