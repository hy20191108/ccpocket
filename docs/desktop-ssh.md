# デスクトップ版のOpenSSH接続

Windows・macOS・Linux版では，マシン追加画面の「OpenSSHで接続」を使い，OSの`ssh`と既存のSSH設定を利用できる．Web版のローカルヘルパーは不要．

この方式を選んだ理由とiOS対応・配布の範囲は[ADR](architecture/adr-desktop-openssh.md)を参照する．

## 接続方法

1. ターミナルで`ssh <接続先の別名>`が追加のパスワード入力なしで接続できるように設定する．`~/.ssh/config`の`Host`，`ProxyJump`，鍵，SSHエージェントをそのまま使う．初回のホスト鍵確認も先に行う．
2. 接続先でBridgeを起動しておく．Bridgeはリモートの`127.0.0.1`で待ち受けてよい．
3. CC Pocketでマシンを追加し，「OpenSSHで接続」を有効にする．「SSH接続先」にSSHの別名，「ポート」にリモートBridgeのポートを入力する．BridgeがAPIキーを要求する場合は，通常どおりAPIキーも入力する．
4. 「追加して接続」を押す．次回起動時も保存した設定から接続できる．

この方式は既存のBridgeへ接続するためのもの．Bridgeのリモート起動・更新は，従来のSSH認証情報を使う設定で扱う．SSHへの対話的なパスワード入力には対応しない．接続できない場合は，同じ端末で別名へのSSH接続とBridgeの起動状態を確認する．

## 接続と互換性の方針

アプリ自身がIPv4ループバック上に一時的な待受口を作り，HTTP・WebSocket接続ごとに`ssh -W 127.0.0.1:<Bridgeのポート> -- <別名>`を起動する．通信は子プロセスの標準入出力で中継し，Bridgeの既存プロトコルを使う．Bridge側の更新は不要．予期しない切断後は，保存済みの同じ接続設定から再接続する．マシンの切替や明示的な切断では，アプリの待受口と子プロセスを閉じる．

ホスト鍵は厳密に照合し，未知・不一致の鍵を自動承認しない．既存のSSH設定や`known_hosts`を書き換えず，秘密鍵をアプリへ複製しない．SSH接続先は別名・ホスト名に使う文字へ制限し，コマンドシェルを経由しない．ローカルの待受口はブラウザー由来のHTTPリクエストを拒否する．SSHの診断出力には接続設定が含まれうるため，アプリのチャットやログへ転送しない．

OpenSSH接続では外側のSSHが暗号化を担当し，Bridgeへの内側の接続は通常のHTTP・WebSocketを使う．HTTPS接続モードとの併用には対応しない．従来のDart SSHクライアントを使う設定は引き続き利用できる．
